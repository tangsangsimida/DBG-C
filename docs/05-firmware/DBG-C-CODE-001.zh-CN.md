# DBG-C 代码规范

**文档编号：** DBG-C-CODE-001　**版本：** V0.1　**状态：** 草案

## 1. 适用范围

本规范适用于 `software/` 中由 DBG-C 项目维护的 C、C++ 和汇编代码。格式规则以 [`software/.clang-format`](../../software/.clang-format) 为准。Linux 内核风格配置及本项目约束以 600C 软件项目的 `.clang-format` 和 `AGENTS.md` 为基线，并按 DBG-C 的语言和目录结构应用。

不对 ThreadX、CMSIS-DAP、WCH EVT、其他第三方或生成文件进行批量格式化。修改这些代码前应遵循其上游格式和许可要求；项目新增适配代码仍遵循本规范。

## 2. 格式与命名

- 使用制表符缩进，每级宽度为 8 列；建议行宽为 100 列。
- 控制语句使用 K&R 花括号；函数左花括号另起一行。C++ 类左花括号另起一行。
- 指针星号靠近变量名；不做连续声明、赋值或尾随注释的视觉对齐。
- 禁止自动重排 include；保持模块头文件、标准库、第三方/RTOS、项目头文件的既定顺序。
- 项目新增文件及符号采用小写 `snake_case`，使用清晰的模块前缀；延续现有 `dbgc_<subsystem>_<purpose>` 命名。不得仅为满足风格而重命名已有公开接口。
- 使用 `clang-format` 检查项目自有 C/C++ 文件；格式配置要求 clang-format 11 或更新版本。

## 3. 注释与 Doxygen

- 新增或修改的项目代码注释使用中文 Doxygen 块注释 `/** ... */`，不使用 `///`。注释放在其完整声明、定义或语句之前，不插入表达式、参数列表、初始化列表或宏表达式中。
- 每个发生修改的项目自有 C/C++ 源文件中，所有逻辑函数都必须有 Doxygen 注释；覆盖率按整个修改后文件统计，不只统计新增函数。函数注释说明用途，并按实际情况说明参数、返回值、状态变化、资源或中断约束。
- 对外接口、结构体、枚举及重要宏应说明用途、取值或调用约束。纯显然的局部语句不添加重复注释；注释应解释意图、约束或非显然行为。
- 不为达到注释覆盖要求而改写未修改的第三方、RTOS、生成或 EVT 原始文件。若确需修改，限定到必要代码并保留来源和改动边界。

## 4. 修改与验证

格式化只覆盖本次修改的项目自有代码，避免无关差异。格式与注释工具位于 [`software/tools/python/`](../../software/tools/python/README.zh-CN.md)，具体命令和扫描边界见其 README。注释率工具是启发式报告，不替代源代码审查。按模块 README 和 `DBG-C-FW-001` 执行适用的构建或主机检查，并单独报告实板验证状态；编译成功不代表硬件行为通过。变更接口或受控文档时，同步检查中英文文件、调用方及相关需求/测试记录。
