DBG-C-FW-001 V0.45 记录了 ThreadX CH585M 实验性 low-level 与 SysTick 接入、WCH EVT 来源、MounRiver GCC 12 环境配置、固定路径两次 clean rebuild 的 ELF/map 一致性，以及启动、上下文和中断路径静态审查。CH585 BSP/适配器已纳入 PoC CMake 构建图中的 `dbgc_ch585_platform` 静态库目标，但 PoC 应用未调用这些接口。主机验证覆盖 FIFO、CMSIS-DAP 命令核心与边界预检/有界 dispatch、SWD 线模型、GPIO/UART/UID 适配器等，详见主文档和 TEST-001。软件放行门已通过，只允许设计带编程/恢复及复位、系统时钟、SysTick、中断活动观测/测量点的限定用途验证板；这不代表芯片运行通过，也不允许冻结产品原理图或 PCB。PoC-1 ThreadX 启动、中断、tick、线程切换/睡眠/唤醒和持续运行仍未做实板验证，相关用例保持未执行；产品硬件冻结未放行。

DBG-C-FW-001 V0.45 records the experimental ThreadX CH585M low-level and SysTick integration, WCH EVT provenance, MounRiver GCC 12 setup, matching ELF/map hashes from two clean rebuilds at a fixed path, and static review of startup, context, and interrupt paths. The CH585 BSP/adapters are included in the PoC CMake graph as the `dbgc_ch585_platform` static-library target, but the PoC application does not call them. Host checks cover FIFO, CMSIS-DAP command core and bounds-preflight/bounded dispatch, SWD line model, GPIO/UART/UID adapters, and related modules; see the main document and TEST-001 for exact evidence. The software release gate has passed for limited-purpose verification-board design only. That board must provide programming/recovery and observation/measurement access for reset, system clock, SysTick, and interrupt activity. This does not establish chip runtime success or release product schematic/PCB freeze. PoC-1 ThreadX startup, interrupts, tick, thread switching/sleep/wakeup, and sustained operation remain unverified on hardware, with related cases Not run; product-hardware freeze is not released.
