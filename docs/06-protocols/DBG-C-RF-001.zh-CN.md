# DBG-C Private 2.4G Protocol Specification

**文档编号：** DBG-C-RF-001　**版本：** V0.1　**状态：** 设计框架；禁止按未冻结字段编码

## 1. 目标与边界

协议用于两台同硬件 DBG-C Probe 之间承载 Debug、UART、控制及后续升级数据。不能把 USB Bulk packet 原样透传作为协议定义。PC 仍通过 USB CMSIS-DAP v2 连接 Host Probe；BLE 管理协议独立。

## 2. 物理层与配对

候选 PHY/信道、跳频、地址、功率、速率、区域法规与 WCH RF SDK API：**待验证**。数据手册只确认集成 BLE/2.4GHz RF 与“2.4G 模式”概述，不能据此确认任意私有 PHY 可用。

配对需建立 Device ID、Peer ID、Pair ID 的语义及唯一性；具体宽度/编码不在 V0.1 冻结。须定义用户授权、配对窗口、认证、解绑、持久化、重配、重放防护与密钥管理。

## 3. 逻辑帧字段（待冻结）

帧至少需表达协议版本、角色/会话、命令或事件类型、序列号、分片信息、长度、数据、校验/认证信息。字段名称、宽度、字节序、对齐、最大帧长、CRC 参数、认证标签和 RF 地址格式全部待验证并在 V0.2+ 规范表冻结；不得作为实现猜测。

## 4. 命令类别

Command/Response/Event 至少覆盖配对/解绑/角色协商、Session 建立、链路状态、Keep Alive、DAP Debug 数据、UART 数据、错误、固件更新控制。目标 MCU 固件 OTA 究竟走 BLE/RF/USB及是否纳入 V1 尚需需求决议；DBG-C 自身 OTA 已属范围，但传输策略待定。

## 5. 可靠性与实时性

需定义 ACK、超时、重试上限/退避、重复检测窗口、分片重组、乱序处理、失联检测、缓存上限、流控与链路恢复。重复 DAP 请求可能产生副作用，接收端须基于会话/序列判重，规则冻结前不得自动重放不安全命令。

QoS 至少区分控制/调试请求响应/UART/升级数据；调度、保留带宽和公平性通过往返时延、长时间 UART 负载及丢包测试确定。CMSIS-DAP round-trip 延迟与 RF 重试风险须测量，不先承诺指标。

## 6. 错误与兼容

定义协议版本协商、未知命令、非法长度、CRC/认证错误、超时、重试耗尽、配对不匹配、目标掉电及恢复事件。Major/Minor 兼容策略待冻结。链路恢复后不得伪报前一会话目标状态。

## 7. 冻结前工作

取得 CH585M SDK 和 RF 示例，验证可用 PHY/并发限制；建立抓包格式与测试工具；用真实 CMSIS-DAP 主机测量往返延迟。随后冻结字段表、状态转换、超时数值、帧向量和兼容规则。
